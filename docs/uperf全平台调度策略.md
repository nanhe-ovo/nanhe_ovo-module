# Uperf-Game-Turbo 全平台 CPU 调度策略速查

数据源：上游仓库 `yinwanxi/Uperf-Game-Turbo` master 分支 `magisk/config/` 下全部 66 份平台配置（`template.json` 为空模板，不参与）。其中 `sdm210.json` 上游文件本身 JSON 不完整（`powerModel` 数组缺 `]`），解析失败，未列入总表。

## 0. 参数速记

- 簇模型 `NxE@T`：N=核心数，E=相对性能（A53@1.0G=100），T=该簇典型频率(GHz)。
- `s/p/f`：sweetFreq 甜点频 / plainFreq 普通频 / freeFreq 空闲频。
- 初始参数 `lat/m/p`：latencyTime（提前升频秒数）/ margin（性能余量）/ predictThd（负载预测阈值）；`limE`=限制低效频点，`!cap`=关闭容量引导。
- 模式栏：`*` 为全局覆盖值，后接各场景覆盖（idle/touch/trigger/gesture/junk/switch），只列与 `*` 不同的键：`lat`/`m`/`b`(burst)/`limE`/`scn`(sched.scene)。
- sched 栏：是否启用线程调度 + 各簇核心数（c0/c1/c2）。

2026 新平台相对仓库既有配置的三个修正方向：

1. **2nm 的高频甜点上移**：2nm 的电压-频率曲线比 3nm 更平，甜点频率可以取典型频率的 0.72–0.75 倍（3nm 时代多为 0.68 倍左右），空闲档可以更高（1.0–1.2G），这代芯片「低频徘徊」反而费电。
2. **5GHz 档收余量**：5GHz 附近每一档都贵，高负载时 margin 收到 0.15–0.2；低负载才给大余量。9600 Pro / 8E6 这类双超大核平台的 `fastLimitCapacity` 不要放开到 360（template 性能档那个值），建议 ≤ 24。
3. **重负载防抖更狠**：2nm + 5GHz 的持续满载温控压力大，`requestBurstSlack` 建议 3000–4000ms，游戏类持续负载不要长期住在 HeavyLoad。
4. **DDR 保底**：LPDDR6 平台 junk 场景可以给 6.4GB/s 量级；MTK 的 `mtk-dvfsrc-devfreq/userspace/set_freq` 节点与 LPDDR6 平台的实际路径需真机确认；骁龙 8E6 沿用 cpubw/llcc 体系时优先保 LLCC 而不是只看 DDR。

### 3.4 落地到本模块时要做的事

1. `customize.sh` 的 `get_config_name` 需要等新机型的 `ro.board.platform` 值（天玑 9600 系预期是新的 mt6xxx 代号，骁龙 8E6 系预期沿用 kona 系新代号），拿到真机值再补映射。
2. 新配置先只写 CPU powerModel + presets，`sysfs.knob` 的 ddrMin / llcc 路径用 `deviceinfo` 实测后逐条加，避免写空节点。
3. 每个新表都走一遍 shell 测试套件的「配置完整性」断言（簇数、频率在表内、margin 范围），再进发布包。
