## 一、一句话版

**南何ovo（性能调度）** 是一个基于 Uperf-Game-Turbo 的 Android 性能调度模块，刷入即带一套纯本地 WebUI：全局模式、分应用规则、CPU/GPU 频率区间、30–240Hz 刷新率（含强制取消静止降频）、机型信息与自动运行日志，都在一块面板里完成；界面是 Miuix 观感白卡 + 悬浮液态玻璃底栏，不联网、不上传任何数据。

## 三、发布帖 / 详细介绍

### 1. 它是什么，解决什么问题

南何ovo把 **Uperf-Game-Turbo** 的调度引擎包进一个 Android 模块外壳，再配一套本地 WebUI。刷入后不需要电脑、不需要 Termux、不需要额外 App：在 KernelSU / APatch 的模块页点开 WebUI 就能改调度。

适合这几种用法：

- 想给不同应用配不同调度（游戏激进、日常省电），又不想手改配置文件；
- 想临时压一下 CPU / GPU 频率区间做测试，且不想盲写节点；
- 被「开机锁 60Hz」「静止掉回 60Hz」折腾过，想一键钉住刷新率；
- 想看清设备真实的频率表与刷新率档位，而不是靠猜；
- 出问题时希望有一份现成的本机日志，而不是临时抓 logcat。

### 3. 面板结构与四个页面

- **总览**：左侧绿色「工作中」状态卡（Root 形态标签、当前模式、模块版本、刷新时间、对勾水印），右侧「已绑定应用规则 / 可调频率节点」两枚统计卡；下面竖排运行状态（Root 方案、当前模式、模块版本、调度引擎、SUSFS 状态、频率基线、系统调优、平台配置）；再往下是性能模式卡、系统调优开关、运行快照（各 CPU / GPU 节点当前频率）。
- **频率**：每个 CPU / GPU 节点一组「最低频率 / 最高频率」下拉，只列出设备真实频率表；下方是「恢复开机频率」；同一页还有「屏幕刷新率」十档、「强制取消静止降频」开关、「恢复默认」。
- **应用**：搜索框 + 应用列表，给单个应用绑定模式（默认 / 省电 / 均衡 / 性能 / 极速等）；已保存的规则可修改、删除。
- **关于**：机型、系统、硬件、内存、存储、屏幕、电池七组信息；「运行日志」卡片；玻璃效果说明与出处。

### 4. 调度：全局模式 + 分应用

- **全局模式**：一排模式卡（常见省电 / 均衡 / 性能 / 极速，具体取决于设备上 `uperf.json` 的 presets），点击即切换，写入 `/sdcard/Android/yc/uperf/cur_powermode.txt`。
- **分应用规则**：绑定结果写入 `perapp_powermode.txt`；应用页可搜索、改绑、删除。
- 包名枚举三路兜底（`pm list packages` / `packages.list` / `dumpsys`），只有全部失败才留空，并自动记一条日志 —— 不会因为 `pm` 退出码 1 就把整页拖进只读演示。

### 5. 频率：只写设备承认的值

- 每个节点（`cpu-*`、GPU）从**设备真实频率表**读候选，最小值 / 最大值只能在表里选；边界不在表内直接拒绝（`invalid frequency bounds`），不会盲写。
- 写入后回读校验；上限成功、下限失败的半改状态会自动回滚，不留半截。
- **恢复开机频率**：本次开机开始时生成的基线（`baseline.<boot_id>.tsv`）一键还原。
- **不做开机持久化**：uperf 切换模式时会重写同一批频率节点，手动区间可能被调度覆盖（面板内已注明）。这是引擎行为，不是开关没生效。

### 6. 刷新率：30–240Hz 十档 + 取消静止降频

- 十档候选 `30 / 48 / 60 / 72 / 90 / 120 / 144 / 165 / 180 / 240`，但**只列出设备声明过的**：把 `dumpsys display` 与 `dumpsys SurfaceFlinger` 两份输出一起解析，同时认 `fps=`、`refreshRate=`、`renderFrameRate=`、`framerate=`、`mRefreshRate=`、`vsyncPeriod=`（纳秒按 `1e9/period` 换算）和 `1880x3008@120.0Hz` 这类写法，取整、限 20–300、去重。
- 没声明的档位：前端虚线置灰不可点；即使绕过界面直接调命令，后端也会用 `<HZ> Hz is not supported by this device` 拒绝。
- **读不到档位表时不整页锁死**：`status` 给出 `refresh_known=0`，前端放开全部十档并提示「已放开全部档位供你尝试」，写入交由系统决定（系统不接受时保持原值），同时日志里记一条，便于你回传 `dumpsys` 排查。
- **强制取消静止降频**：开启后除写 `peak_refresh_rate`，还把 `min_refresh_rate` 钉到同档，画面静止、熄屏回来不会偷降到 60Hz；关闭则删除下限，交回系统动态调节。写下限失败会把上限还原成原值并报错。
- **开机锁 60Hz 修复**：开机脚本按保存的目标值重写；读不到档位就沿用当前刷新率并写日志，不再把设备锁死在 60Hz。

### 7. 系统调优开关

默认开启：开机执行 uperf 上游的 `powercfg_once.sh` / `platform_special.sh` / `miui_migt.sh`（压平厂商调度、处理温控进程等）。关闭后只启动 uperf 引擎本身，不再改动厂商进程；状态存于 `/data/adb/nanhe_ovo/tune_disabled`，**改动下次开机生效**。

### 8. 关于页：机型与系统信息

品牌 / 型号 / 制造商 / 设备代号 / 指纹；Android 版本 / API 级别 / 安全补丁 / 当前槽位 / SELinux / Build / 内核版本；主架构 / 支持 ABI / 核心数 / 硬件 / 主板 / CPU 温度；RAM 总量 / 可用 / 已用 / 交换分区；存储总量 / 可用 / 已用；屏幕分辨率 / 像素密度 / 当前刷新率；电池电量 / 温度 / 健康 / 状态 / 技术 / 充电功率。

### 9. 运行日志：出问题自动记

- 位置 `/data/adb/nanhe_ovo/log.txt`，一行一条：时间 / 级别（info、warn、error）/ 标签 / 正文，最多 200 行，超出裁掉最早的。
- 自动记录：任何后端命令失败（错误原文）、刷新率档位表或当前值读不到、本次开机没有基线、`uperf.json` 缺失、应用枚举报错、开机应用刷新率的每一步、页面自身发现的问题。
- 同一开机内同类诊断只记一次（按 boot_id 去重），轮询不会刷屏；「清空日志」会连去重标记一起清掉，之后新问题还能重新记。
- 页面可「刷新日志 / 清空日志」；**只写本机，不上传**。

### 10. Root 形态与 SUSFS 状态

- 首页状态卡标签自动显示 `LKM` / `GKI` / `APatch` / `Magisk`：`/data/adb/ksu` 或 `ksud` 存在即 KernelSU，再看 `/sys/module/kernelsu` —— 有 = `KernelSU · LKM`（`kernelsu.ko` 作为模块挂上），没有 = `KernelSU · GKI`（编进内核镜像）；`/data/adb/ap` → `APatch`；`/data/adb/magisk` → `Magisk`；都没有 → `未知`。只判断存在性，不执行 `ksud`、不读它的配置。
- `status` 另输出 `info susfs`：`已加载` / `未加载（SUSFS Guard 已安装）` / `未安装`；已装未加载会自动记一条 warn，指向 `/data/adb/modules/susfs_guard_lkm/load.log`，方便排查 LKM 版 SUSFS 的加载失败。

### 11. 界面与底栏玻璃

- 浅灰底 + 纯白 28px 圆角卡；四个页面共用同一套卡片、输入框、开关行。
- 底栏是**唯一保留液态玻璃**的地方：悬浮胶囊，离底边 14px（另加 `env(safe-area-inset-bottom)`），`blur(22px) saturate(240%) contrast(124%)`，上下各 16px 折射带、左右各 2px 红/青色散，白渐变 `50% / 34% / 42%`，滚动时能看到下面卡片透上来。
- 当前页一枚圆形玻璃镜片，切换页面沿四格滑过去；页面滚动时底栏按滚动速度轻微倾斜 / 横向拉伸 / 下沉，停下后弹簧回位；按下有回弹。
- 旧 WebView 不支持 `backdrop-filter` 时，底栏回退成不透明胶囊；深色模式另有一套玻璃令牌。

### 12. 安装与使用

1. 确认设备是 **arm64**。
2. 管理器刷入 `nanhe_ovo-v1.3.1-20261121.zip`：Magisk → 模块 → 从本地安装；KernelSU / APatch → 模块 → 安装。
3. 重启（`post-fs-data` / `service` 会拉起 uperf 并应用开机策略）。
4. 打开面板：KernelSU / APatch 管理器 → 模块 → 南何ovo → 打开 WebUI；Magisk 本体没有模块 WebUI，可用 KsuWebUIStandalone 等工具打开 `/data/adb/modules/nanhe_ovo/webroot/index.html`。
5. 首次进入若显示「只读演示」，说明 WebUI 没拿到 root 桥接，此时所有写入都会被禁用（这是保护，不是故障）。

升级会保留 `uperf.json.bak`；卸载会还原 `peak_refresh_rate` / `min_refresh_rate`、删除 `/data/adb/nanhe_ovo`（含日志）。

### 13. 常见问题

**Q：为什么刷新率档位是灰的？**
A：设备没在 `dumpsys` 里声明那一档。换成它声明过的档位即可；若整页都灰，说明这次一个档位都没解析到，面板会放开全部十档并给出提示，你可以照提示尝试，同时把日志里的那条记录回传。

**Q：频率改完过一会又变回去了？**
A：uperf 切模式会重写同一批节点，这是引擎行为。要稳定生效，先在「频率」页恢复默认再观察，或在固定模式下手动限制。

**Q：会不会偷偷联网 / 上传数据？**
A：不会。WebUI 是本地 HTML/CSS/JS，无远程资源；日志只写 `/data/adb/nanhe_ovo/log.txt`。

**Q：日志在哪，怎么给我看？**
A：`/data/adb/nanhe_ovo/log.txt`；面板「关于 → 运行日志」也能直接看，最多 200 行。

**Q：和 SUSFS Guard (LKM) 冲突吗？**
A：本模块不加载/卸载任何内核模块，也不碰 `kallsyms`、`kptr_restrict`、`/proc/susfs_*`。若 SUSFS 报加载失败，先看它的 `load.log`；想直接判定与本模块是否相关，可临时 `touch /data/adb/modules/nanhe_ovo/disable` 重启对比。

### 15. 已知边界（写清楚，免得误会）

1. 不是超频 / 降压 / 改电压工具，只写设备已暴露的频率与刷新率参数。
2. 频率区间不持久化；刷新率有开机应用，但依赖系统设置项被接受。
3. 液态玻璃是 CSS 近似（模糊 + 饱和度 + 边缘色散 + 高光），**做不到** Backdrop `lens()` 的逐像素折射；亮色背景下会偏奶白。
4. LKM / GKI 判断依据 `/sys/module/kernelsu` 是否存在，属启发式；页面会同时显示完整值供比对。
5. APatch / Magisk 只按 `/data/adb/ap`、`/data/adb/magisk` 目录识别，不解析版本号。
6. 日志最多 200 行、只在本机；面板不联网。
7. 未在全部机型验证；当前为 Android 17 / MT8799 真机对照 + Ubuntu 容器 POSIX 后端测试（207 条断言）+ Windows 无头 Edge 渲染测试（59 条断言）。
