# 线程调度方案推测（Chase dream 分析 × 全平台 CPU 数据）

> 版本：2026-11-19 推测稿。仅分析，未写入任何模块。
> 数据来源：`docs/uperf全平台调度策略.md`（上游 66 份平台配置 + 23 份自拟推测配置 + 2026 新芯片参数）、`Chase dream V7.0` 静态分析结论、`module/config/mtd9400.json` 现有 sched 规则。

---

## 1. 一句话结论

Chase dream 证明「包名/线程名 → CPU 亲和性」的静态放置思路有效，但它的规则全部硬编码成 `0-7` 数字、隐含 `4+3+1` 拓扑假设。结合已收集的 CPU 数据，全平台线程调度的正确做法是：

**规则写语义（main/render/worker/io），掩码由拓扑解析；按拓扑类生成标准模板，按芯片微调；静态放置打底，动态反馈兜底。**

---

## 2. 从 Chase dream 分析中保留什么、改什么

| 结论 | 处置 |
| --- | --- |
| 主线程绑大核、渲染绑中核、后台下沉，思路正确 | 保留，作为角色分层基础 |
| 线程级规则覆盖包级默认、支持通配符 | 保留语义，优先级定为：精确线程名 > 通配线程名 > 包级默认 |
| 规则硬编码 0-7、假设 4+3+1 | **废弃**。改成语义核组 token，按实际拓扑解析 |
| 安装器算了 e/p/hp 分组却只打印不落地 | **修复**。探测结果直接生成掩码映射 |
| 18 个重复包级键、12 个目标冲突 | **修复**。一包一条包级规则，去重后入库 |
| 模块 id=mls 却去 `/data/adb/modules/AppOpt` 找旧配置 | **修复**。升级保留本模块目录的用户规则 |
| core_ctl 一刀切 min=max 全核在线 | **收窄**。只在前台应用命中了 p 类规则时保大核簇在线，退出恢复 |
| 无日志、无 PID 锁、stdout 丢 /dev/null | **补**。写日志文件 + pidfile |
| 线程名 15 字符截断 | 规则用 ≤15 字符前缀匹配 |
| 不调优先级/不调频 | 位置层保持纯亲和性；优先级与频率交给 uperf 层，避免互相覆盖 |

## 4. 语义核组与线程角色

### 4.1 语义 token

```
l   = 能效簇（全大核芯片上=最低频簇，只承担低负载区角色）
m   = 中簇（多核性能簇，渲染/worker 的主战场）
b   = 大核簇（多核）
p   = Prime 簇（单核或双核，只给串行关键线程）
组合：l+m、m+b、l+m+b、all（0..N-1）、all-p
```

运行时从 `/sys/devices/system/cpu/cpu*/cpufreq` 读 `related_cpus` + `cpuinfo_max_freq`，按频率升序给簇编号，再解析 token → 实际 CPU 掩码。**规则文件里永不出现裸数字。**

### 4.2 线程角色分层（复用 Chase 规则库语义，去重）

| 角色 | 代表线程名（Chase 规则库里验证过的） | 掩码 |
| --- | --- | --- |
| MAIN 串行关键 | `UnityMain`、`GameThread`、`UEGameThread`、`MainThread-UE4`、`CrGpuMain` | `p` |
| RENDER 渲染 | `UnityGfxDeviceW`、`RenderThread`、`RHIThread`、`GLThread` | `m` |
| WORKER 并行 | `Job.worker*`、`Thread-*`、`TaskGraphNP*`、`Unity Worker` | `m`（性能档放宽到 `m+b`） |
| IO/ASYNC 加载网络 | `FAsyncLoading`、`AsyncReadManage`、`OkHttp*`、`TVKDL-*` | `l+m` |
| BINDER/NATIVE | `binder:*`、`*binder`、`NativeThread` | `m` |
| AUDIO | `AudioTrack`、`FastMixer`、音频解码线程 | `l` |
| SYS UI | `systemui`、`surfaceflinger` 主线程 | `m`（不与游戏主线程抢 `p`） |
| 后台/通用应用 | 全部线程 | `l+m`；后台进程 `l` |

匹配优先级：**线程名精确 > 线程名通配 > 包级默认**；一个包只允许一条包级规则（解决 Chase 12 组冲突）。

### 5.1 2024–2026 旗舰逐芯片要点

- **8 Gen 3（G）**：唯一可直接沿用 Chase 数字规则的平台，保留其 422 条规则库去重后作为 `sdm8g3` 模板。
- **8 Gen 2 / 7+ Gen 3 / 8s Gen 3（F）**：Chase 的 `2-6` 会夹进 2 颗 A510，必须改成 `3-6`；`2-4` 渲染组同样改成 `3-6` 内的子集。
- **8 Elite / 8E6（K）**：没有小核。Chase 把 0-1 当小核、2-6 当性能核，会浪费 2 颗 Perf 且只留 1 颗 Prime。正确映射：默认 `0-5`，MAIN `6-7`（双 Prime 都可用），低负载区 `0-3`。
- **天玑 9300（J）**：4+4 全大核，无小核簇。默认 `4-6`，MAIN `7`，A720 簇 0-3 当低负载区。
- **天玑 9400 / 9500s（C/N）**：1+3+4，`0-3` A720 / `4-6` X4 / `7` X925，与 8G1 时代 4+3+1 掩码一致，仅频率更高。
- **天玑 8400（C）**：全 A725 的 4+3+1，掩码同 C 类。
- **天玑 8500（L）**：8×A725 全等单簇，不做分层，仅给 MAIN 固定 `7` 减少跨核抖动，RENDER `4-6`。
- **天玑 9600 Pro / 8E6X（M）**：双超大核 `6-7`。MAIN 独占 `6-7`（一颗跑主线程、一颗留给渲染借核），默认 `0-5`。
- **Exynos 2400（I）**：十核 4+5+1，掩码 0-9，注意规则文件不能沿用 8 核假设。
- **Exynos 2700（O）**：1+1+4+4，`8` 为中高单核、`9` 为 Prime，MAIN `9`、RENDER `4-7`。

## 6. 模式分档（含超频）

线程层本身不能超频，但「独占 Prime + 全核在线」可以放大调频层超频的效果。四档联动：

| 角色 | 省电 | 均衡 | 性能 | 超频（联动 crazy 档） |
| --- | --- | --- | --- | --- |
| MAIN | p | p | p | p（并从其余掩码中剔除 p，独占） |
| RENDER | m | m | m+b | m+b |
| WORKER | m | m | m+b | all-p |
| IO | l | l+m | l+m+b | l+m+b |
| 游戏默认 | m | m+b | m+b | all-p |
| 普通应用 | l+m | l+m | all | all |
| core_ctl | 随系统 | 游戏前台保 m+p | 保 m+p | 全簇保核 |

超频档对应调频层 `fastLimitCapacity=999 / margin=1.0 / ddrMin 6.4GB/s` 那一档（crazy 已实现），线程层配合「Prime 独占 + 保核」，避免超频时主线程被别的线程挤下大核。

## 7. 动态反馈（静态打底之后的第二步，推测）

解决之前实测暴露的两个问题：

1. **骁龙「小核不调用」**：不是逼小核跑游戏主负载，而是把 IO/音频/后台线程**显式**放进 `l` 或 `l+m`，且保证它们 nice 不低于 4，让小核有稳定负载又不抢关键路径。8 Elite 无小核，低负载区由 Perf 簇 0-3 承担，不强行「调用小核」。
2. **天玑 GPU 跳频/降频**：RENDER 线程固定在 `m` 簇内不跨簇迁移，减少渲染负载毛刺对 GPU/DDR DVFS 的联动扰动；频率层配合 junk 档 `ddrMin 5.5GB/s`（mtd9400 已实现）。

动态规则（每 3s 采样线程 utime/stime + `/proc/stat` + thermal zone）：

- 渲染借核：RENDER 线程利用率 >85% 连续 3 次且 MAIN <60% → RENDER 掩码临时并入 `p`；
- 加载降级：MAIN 利用率 <20% 连续 5 次（过场/加载）→ MAIN 临时降 `m+b`，Prime 交还系统；
- 温控避让：Prime 簇温度超阈值 → MAIN 临时降 `m+b`，防厂商温控硬降频；
- 启动宽限：新进程前 3 秒给 `all`，避免开局绑核卡顿，3 秒后再收敛。

## 8. 与现有模块的衔接（落地方式，未执行）

1. 南何ovo（uperf）已有 `sched.rules`（regex + 亲和类 c0/c1/c2 + 优先级类），mtd9400.json 里 `gtmain→c2 / gtcoop→c1` 就是雏形。方案 = **包级默认决定应用类，线程级规则决定特殊线程类，类→掩码由拓扑解析**，一套规则全平台复用。
2. Chase 的 422 条包名/线程名规则**保留为规则库**（去重 18 键、解决 12 组冲突），数字掩码替换为语义 token，`sdm8g3` 直接可用。
3. 每平台补一份 topo 掩码（运行时从 cpufreq 读，或预置表回退），替代硬编码。
4. core_ctl 改为「前台命中 p 类规则才保核」，退出恢复；不再全局 min=max。
5. 日志落盘 + pidfile；规则文件支持 inotify 热载；升级保留用户规则（修复 id=mls 与 AppOpt 目录不一致的问题）。

## 9. 验证方法

```sh
# 验证绑定是否生效
cat /proc/<pid>/task/<tid>/status | grep Cpus_allowed_list
# 观察线程是否跨簇迁移、各簇负载
cat /proc/stat ; cat /proc/<tid>/sched
```

验收标准：主线程长期只出现在 `p` 掩码内；渲染线程出现在 `m` 掩码内且迁移次数下降；小核簇负载由 IO/音频线程填充而非空闲；帧率曲线大卡顿次数下降。
